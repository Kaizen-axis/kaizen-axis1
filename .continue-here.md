### Backend

`supabase/functions/_shared/login-security.mjs` adiciona:

- `LOGIN_LIMIT = { limit: 10, windowSeconds: 60 }`;
- `isLoginCaptchaRequired(rawValue)`, que só desliga CAPTCHA para o literal `false`;
- rate limit fail-closed usando `increment_request_counter`;
- bloqueio server-side de perfis `inativo`/`inactive`;
- revogação global via `adminClient.auth.admin.signOut(accessToken, 'global')` quando o perfil não pode receber sessão.

`secure-login/index.ts` agora:

1. calcula `LOGIN_REQUIRE_CAPTCHA` com default seguro;
2. exige configuração/validação Turnstile se CAPTCHA estiver obrigatório;
3. aplica rate limit antes do password grant;
4. autentica senha;
5. valida o perfil ativo antes de retornar tokens.

### Frontend

`src/pages/Login.tsx` agora usa:

- `VITE_LOGIN_REQUIRE_CAPTCHA !== 'false'` como default seguro;
- bypass somente no login existente quando a flag for literalmente `false`;
- CAPTCHA sempre exigido no caminho de signup;
- signup oculto durante o break-glass;
- recuperação de senha substituída por aviso temporário durante o break-glass;
- fluxo MFA e checagem cliente de perfil preservados.
